Project I

Brain2Text 2025

Multi-Architecture Ablations

A systematic ablation study on a BCI speech decoding pipeline that maps intracortical neural recordings to text. The core question: which architectural and training choices most reduce word error rate (WER), and can audio-pretrained LLMs close the gap to the published benchmark (WER 0.1567, Aero1-Audio backbone)?

Baseline & Current Training Status

Pipeline BIT_Transformer (7L, 384d, RoPE, session read-in, SSL pretrained) → MLP Projector (384→1024→1024→1536) → Qwen2.5-1.5B + QLoRA QLoRA config r=8, α=32, dropout=0.2 · 7 target modules · 4-bit NF4 quantisation Auxiliary losses CTC (weight 0.3) + Contrastive ModalityAlignmentLoss (weight 1.0, learnable temperature) Training status Active  Epoch 65 / 150  ·  Best WER 0.3673  ·  LR = 6.25×10⁻⁶ Inference fix Nucleus sampling applied (paper §A.3): top_p=0.9, temperature=0.7, max_new_tokens=25 Hardware Training — A100 40 GB (JarvisLabs instance 417023)  ·  Local dev — RTX 4050 6 GB Target WER < 0.10  ·  Published best (Aero1-Audio backbone): WER 0.1567
Realistic ceiling with text-only Qwen2.5-1.5B: ~WER 0.25–0.30. The published 0.1567 uses Aero1-Audio (audio-pretrained Qwen), a fundamental prior advantage. The nucleus sampling fix is expected to yield 3–8% relative WER improvement for free. Audio-pretraining experiments (Track A, C) are the primary path to the 0.10 target.

Toy Training Protocol

All ablation experiments run first on 15% of training data, 20 epochs, 200 batches/epoch (~20 min local) before any full A100 commitment. Promotion decision uses WER slope (epoch 2→20): ≥5% relative → full cloud run immediately; 3–5% → combine + retry; <1% → discard.

Five Experiment Tracks

Track A  ·  4 experiments

Pretraining Modality

Why does audio pretraining help neural decoding? Comparative analysis: audio vs image/video vs text-only LLM backbones. Tests four mechanistic hypotheses (phoneme prior, spoken language prior, embedding geometry, temporal structure).

A1 CKA alignment  ·  A2 Spoken perplexity  ·  A3 Phoneme probe  ·  A4 Full E2E WER comparison
Track B  ·  5 experiments

Encoder Architecture

Five drop-in replacements for BIT_Transformer — all output (B, T_patch, 384). ConformerXL (spike-jitter correction), HRM (dual-timescale DEQ), MambaPOSSM (SSM + cross-attention tokeniser), MoE (6 specific + 2 shared experts), ZenBrain (episodic memory).

B1 ConformerXL  ·  B2 HRM  ·  B3 MambaPOSSM  ·  B4 MoE  ·  B5 ZenBrain
Track C  ·  3 experiments

LLM Decoder Variants

BIT encoder held constant; only the LLM decoder changes. Tests three audio/multimodal LLMs as drop-in Qwen2.5-1.5B replacements. C3 (WhisperQwen) is the only locally runnable audio-LLM option.

C1 Qwen2-Audio-7B  ·  C2 Phi-4-Multimodal  ·  C3 Whisper-Large-v3 + Qwen2.5
Track D  ·  4 experiments

Loss Function Design

Ablations on the three-term loss: CE + 0.3×CTC + 1.0×Contrastive. Tests CTC annealing schedules, contrastive weight grid, topographic regularisation (FFN cortical map constraint), and label smoothing for low-data regimes.

D1 CTC annealing  ·  D2 Contrastive weight  ·  D3 Topographic loss  ·  D4 Label smoothing
Track E  ·  3 experiments

Projector Architecture

Currently: MLP 384→1024→1024→1536 + LayerNorm. E2 (Q-Former cross-attention projector with N learned queries) is the highest-impact change — produces fixed-length output independent of neural sequence length.

E1 MLP depth variants  ·  E2 Q-Former projector  ·  E3 Patch-size × token-count grid

Track D — Loss Function Design

ID Ablation Variants tested HW
D1 CTC Annealing CTC weight 0.3→0.0 over 75 epochs. Variants: fixed 0.3 / linear / step / zero from epoch 0. Tests whether CTC constrains late E2E specialisation. Local
D2 Contrastive Weight Grid: {0.0, 0.1, 1.0, 2.0}. If weight=0 improves WER the contrastive loss is conflicting with CE and should be rescheduled or removed. Local
D3 Topographic Loss Forces FFN first-linear weights to form 2D cortical-like maps (Gaussian blur + cosine similarity). Zero new parameters. Weight ∈ {0.001, 0.01, 0.1}. Requires d_hidden=1024 (=32²). Local
D4 Label Smoothing ε ∈ {0, 0.05, 0.10, 0.20}. ~1000 BCI samples makes overconfidence on training sentences a real risk. Cross-entropy KL-softened target. Local

ID Variant Description HW
E1 MLP Depth 3-layer MLP (current: 384→1024→1024→1536) vs 5-layer vs Gated MLP with multiplicative interaction (element-wise gate × value). Tests whether projector depth is the semantic bridge bottleneck. Local

Project II

DietCorp-ZenBrain Memory BCI

On-Device Deployment Study

A memory-augmented speech BCI targeting ALS and brainstem-stroke patients, with a clinical requirement for streaming, on-device inference without cloud dependency. The study asks whether the composite system can be deployed on Google's Coral platform, and whether multi-tier layered memory improves test-time adaptation under day-to-day electrode distribution shift.

Research Question

Base architecture DietCorp-Compact (arXiv:2507.02800) — time-masked Transformer + DietCORP TTA. Chosen as the only design simultaneously delivering low WER, streaming/real-time decoding, low compute (on-device feasibility), and TTA-based robustness to distribution shift. Extension Multi-tier memory layer inspired by ZenBrain's 7-layer neuroscience architecture. Hypothesis: layered memory with differentiated time constants improves TTA under distribution shift beyond single-shot per-trial adaptation. Target hardware Google Coral platform (Edge TPU) — the only candidatefor truly on-device, battery-powered BCI inference at clinical scale. Core sub-questions (a) Can DietCorp inference run on Coral? (b) Can DietCorp + ZenBrain memory + TTA run on Coral? (c) Which performance metrics can the NPU simulator capture vs. which require real silicon? Audit stance Explicitly skeptical — not a rubber stamp. Goal is to identify simulator-free, custom-instrumentation, and real-silicon-required claims separately before any hardware purchase. Feasibility audit Complete  28 May 2026  ·  Coral_Feasibility_DietCorp_ZenBrain.md
Why Coral? Edge TPU delivers ~4 TOPS at 2W TDP — the only commercially available NPU meeting both the latency budget (<50ms per utterance) and the power budget (<5W) required for an untethered, battery-powered BCI device. Alternatives (Jetson Orin Nano, Hailo-8, phone NPUs) are evaluated as part of the platform comparison study (Stage 3).

Six Investigation Modes

All six modes are active throughout the four stages — not sequential phases. Each stage draws on a different weighted combination.

Mode 1  ·  Architecture & Paper Reading

Close reading of DietCorp and ZenBrain to extract op graphs, parameter counts, and behavioural mechanisms. Produces the forward-pass op inventory used in Mode 3.

Mode 2  ·  Toolchain & Platform Research

Coral NPU simulator stack (MPACT + Verilator), Edge TPU compiler, LiteRT / MLIR / IREE, int8 PTQ/QAT, op-compatibility lists. Skeptical assessment of simulator maturity claims.

Mode 3  ·  Op-Level Compatibility Analysis

For every op in DietCorp's forward pass: does it map natively, fuse, fall back to vector execution, or force CPU offload? Result is a per-op placement table with estimated cycle cost.

Mode 4  ·  Placement Reasoning

For each ZenBrain memory tier and TTA algorithm: NPU vs host CPU vs off-device. Structured argument from access pattern, latency budget, memory size, and whether the subsystem is inside the streaming loop.

Mode 5  ·  Alternative Platform Scan

Controlled comparison: Coral USB Accelerator, Coral NPU sim, Jetson Orin Nano, Hailo-8, Apple Neural Engine, Qualcomm Hexagon, and Renode (whole-SoC co-simulation). Controlled variables: latency, power, SDK maturity, op coverage.

Mode 6  ·  Simulator vs Real-Silicon Separation

Strict classification of every metric as (i) simulator-free, (ii) requires custom instrumentation, or (iii) requires real silicon. This discipline prevents thesis over-claiming and scopes hardware purchase decisions.

Risks & Open Decisions

Four decisions resolvable in a single advisor 1:1. None are blockers for Stage 1 or Stage 3 parallel setup.
Decision 1 Which Coral platform anchors the thesis? Coral USB Accelerator (first-gen) for real wall-clock latency measurements, or new Coral NPU for cycle-level simulator insight? Trade-off: hardware availability vs. toolchain maturity vs. what the thesis needs to claim.
Decision 2 Is on-device TTA non-negotiable for the clinical narrative? If TTA gradient steps must run on-device, the ZenBrain host-CPU placement is insufficient and the feasibility claim weakens. If TTA can run at session start only (offline), host-CPU is defensible.
Decision 3 How "inside" the streaming loop does the memory layer need to sit? Retrieval latency budget: if memory cross-attention must complete within the 50ms utterance window, NPU placement is required. If asynchronous retrieval is acceptable, host-CPU is sufficient.
Decision 4 Full platform shortlist for the comparison study. Current candidates: Coral USB, Coral NPU sim, Jetson Orin Nano, Hailo-8, Apple Neural Engine, Qualcomm Hexagon, Renode. Depends on what hardware is available in lab and advisor preference for the comparison frame.
Risk Coral simulator maturity. MPACT + Verilator is a research-grade tool, not production-validated. Cycle counts may not match USB Accelerator wall-clock times within a factor of 2. Stage 3 Track B (USB Accelerator) is the planned mitigation — real silicon validates simulator claims before any thesis commitment.
