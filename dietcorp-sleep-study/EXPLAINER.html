Deeper “Sleep” Consolidation under Electrode Drift

A standalone, self-contained study built around a single experimental axis — N, the depth of offline memory consolidation in DietCorp-style test-time adaptation. This document is grounded entirely in the repository implementation (core/, a100/, configs/, tests/, run_study.py) and the three source papers.

1.  Research Question and Hypothesis

The central concept: DietCorp’s single adaptation step is the N=1 special case of an offline “sleep” loop. The study asks whether more consolidation depth pays off precisely because electrode drift is a sequential problem.

Hmain — in plain language

A brain-to-text decoder is trained once and then frozen. As the days pass, the recorded neural signal slowly changes (electrode impedance shifts, baselines move), so a decoder that worked on day 1 decodes worse and worse on later days. DietCorp fixes this with a tiny per-trial recalibration: after each decoded sentence it takes one gradient step on just the input layer. The hypothesis here is that replacing that one step with N offline consolidation steps — done entirely between sentences, where there is no latency budget — reduces the error under drift, while the decode itself stays a single forward pass so the clinical wake-time latency never grows.

Hmain — formally

Let WER_last(N) be the word-error-rate on the last held-out day after running the adaptation loop with consolidation depth N ∈ {0,1,2,4,8}. As recorded in the parent RESEARCH_NOTES.md §3 and operationalised by run_study.py / a100/collect_and_plot.py:

# H_main (falsifiable form)
WER_last(N)  decreases as N increases        # gains grow with consolidation depth
wake_latency_ms(N)  ≈ constant in N           # the clinical guarantee: wake = 1 forward pass
consolidate_ms(N)   ≈ N · c   (linear in N)   # all extra compute is offline

# Decision gate actually used (README line 29):
H_main supported  iff  C2(N>1) < C1(N=1)  on later days  AND  wake_latency flat across N
Why deeper N is expected to help The “Do Language Models Need Sleep?” result is that converting observed context into useful weight memory is itself a hard computation that one pass does not finish, and that the gains from extra offline passes are largest on sequential tasks where today’s correct state depends on yesterday’s. Each consolidation step is one AdamW update toward a pseudo-label; with a good label, more steps move the input layer further along the drift-correction direction without ever touching wake-time latency. Hence: deeper N → more drift correction at flat wake cost.

Why electrode drift is fundamentally a sequential adaptation problem

The signal statistics on day d are not an independent draw — they are day d−1’s statistics plus an incremental physical shift (impedance build-up, micro-motion, baseline drift). The distribution shift therefore accumulates: errors compound across adjacent days, exactly the structure of a sequential problem. The study honours this in code by loading sessions in their real chronological order — drift_eval.load_real_sessions parses the date out of each trial key (t15.YYYY.MM.DD…) and returns an OrderedDict sorted by date, so the day-to-day sequence is genuine rather than a reshuffle.

Why this makes the sleep-paper prediction apply The sleep paper’s prediction (“gains from N grow on sequential problems”) is conditional on the task being sequential. Because drift is a cumulative, day-ordered process, the prediction is directly transferable: if deeper offline consolidation helps anywhere, it should help here. This is the logical bridge that makes Hmain well-posed (parent RESEARCH_NOTES.md §2b).

3.  System Architecture and Wake/Sleep Loop

One model, two operating modes. Wake is a single latency-bounded forward pass; sleep is the unbounded offline loop that does all the adaptation.

The model

The decoder is CTCPhonemeModel = BIT_Transformer encoder + Linear CTC head (core/model.py, core/bit_encoder.py). The encoder is a 7-layer RoPE transformer with a per-session linear read-in, a patch embedding over patch_size=5 time bins, and embed_dim=384; the head is Linear(384 → 42) for 42 CTC classes (0 = blank, 1…41 = phonemes). Weights are restored from best_model_per.pth by build_ctc_model, which first reconstructs the exact per-session read-in set baked into the checkpoint (session_ids_from_checkpoint).

input_dim = 512 embed_dim = 384 num_layers = 7 num_heads = 6 patch_size = 5 num_phonemes = 42 (blank + 41)

Wake path — one forward pass

Implemented by TTAConsolidator.logits() and drift_eval.decode_phonemes():

neural (T,512)
  → encoder.read_in[session]        # per-session linear recalibration
  → patch: LN1 → Linear → LN2       # patch_size=5 bins per token (100 ms)
  → 7 × RoPE Transformer blocks     # FROZEN at wake
  → final LayerNorm
  → (optional) episodic memory read # cross-attn + gated fuse  (EpisodicBuffer.forward)
  → CTC head  Linear(384 → 42)      # phoneme logits
  → greedy / beam decode → phonemes
  → lexicon DP (wer_decode.decode_words) → words

Sleep path — between trials

Implemented by run_study.run_condition() driving TTAConsolidator.consolidate():

(trial just decoded)
  → pseudo_label(clean trial, mode = self | lm | oracle)     # the target to learn toward
  → confidence-gated WRITE of the latent into episodic memory # EpisodicWritePolicy (conf ≥ 0.5)
  → ReplayStore.sample(k): pick top-K past trials by priority # Simulation-Selection
  → build batch = [current trial] + [replay trials]
  → augment each: 64 time-masked copies (~53% masked)
  → for n in 1..N:                                           # the N-step "sleep"
        loss = mean CTC(aug, pseudo_label)
               (+ episodic_weight · MSE(latent, recalled.detach()))   # memory anchor
        AdamW step on patch-embed + read-in ONLY              # grad-clip 1.0, lr 1e-5
Wake latency is independent of N consolidate() times exactly one clean forward pass as wake_latency_ms before the N-loop runs, so it cannot depend on N by construction. The N steps are timed separately as consolidate_ms.
Consolidation cost ≈ linear in N The loop body (forward + backward + AdamW on the augmentation batch) runs max(1, N) times, so wall-clock consolidate_ms grows roughly linearly in N — confirmed empirically (RESEARCH_NOTES §8: 3 → 4 → 24 → 101 ms for N = 1,2,4,8).
Only the intended components update during sleep The AdamW optimiser is constructed over target_params = patch_embed_params(model) only — parameters whose name contains "patch" or "read_in" (patch LayerNorms + patch embedding + per-session read-in). The 7 transformer blocks, the final LayerNorm, the CTC head, and the episodic memory’s attention/gate are not stepped. The unit test test_consolidate_lowers_loss_and_touches_only_target asserts the head weight is byte-for-byte unchanged after consolidation.

4.  Significant Code Changes (file by file under core/)

Each module below is quoted with its real signatures from the repository. Two are copied-and-extended from the parent repo (consolidator, episodic_memory); lm_refine and replay are new; the rest are standalone copies + the real-drift loader.

core/consolidator.py — the N-step “sleep” engine

DietCorp TTA generalised to N passes, with an optional episodic-memory anchor, three pseudo-label modes, and replay-batch consolidation. Key signatures:

core/consolidator.py
@dataclass
class TTAConfig:
    n_aug=64 · mask_frac=0.53 · mask_span=4 · lr=1e-5 · grad_clip=1.0
    blank=0 · confidence_threshold=0.0 · min_pseudo_len=1
    episodic_weight=1.0 · lm_beam=8 · lm_weight=0.5

class TTAConsolidator:
    def __init__(self, model, target_params, memory=None, lm=None, config=None)
    def logits(self, neural, session_id=None, write_memory=False)      # wake forward (thru memory)
    def augment(self, neural, generator=None)                          # 64 time-masked copies
    @torch.no_grad()
    def pseudo_label(self, neural, mode="self", true_labels=None, session_id=None)
    def consolidate(self, trials, n_steps=1)                          # the N-step loop → metrics dict
  • N-step loop. consolidate() times one clean forward as wake_latency_ms, then runs for _ in range(max(1, n_steps)): zero_grad → loss.backward → clip_grad_norm_(1.0) → AdamW.step, timing the whole loop as consolidate_ms. It returns loss_before, loss_after, params_changed, and the two latencies.
  • Memory anchor. Inside _ctc_term(), when a memory is attached the loss becomes CTC + episodic_weight · F.mse_loss(memory_query, memory_retrieved.detach()) — the recalled representation is the detached, stable target the current latent is pulled toward.
  • LM / oracle pseudo-labels. pseudo_label() branches by mode: oracle → use the provided true_labels; lm → ctc_beam_search(log_prob, lm=self.lm, …) for a denoised label; self → ctc_greedy_decode() (DietCorp’s original behaviour). Confidence = mean per-frame max-softmax probability.
  • Replay batch. consolidate(trials, …) takes a list; trials[0] is the current trial and any extras are prioritized replay items. Every entry is augmented once and the per-step loss is the mean CTC over all of them.

core/episodic_memory.py — ZenBrain episodic stage

core/episodic_memory.py
class EpisodicWritePolicy:
    def __init__(self, confidence_threshold=0.5)
    @torch.no_grad()
    def write(self, module, latent, confidence=None, session_id=None) -> int

class EpisodicBuffer(nn.Module):
    def __init__(self, embed_dim=384, buffer_size=256, n_heads=6,
                 confidence_threshold=0.5, gate_init=0.1)
    def forward(self, x, write=True, confidence=None, session_id=None)   # (B,T,E) → fused (B,T,E)

def episodic_consistency_loss(query, retrieved, weight=1.0)            # MSE(query, retrieved.detach())·w
  • Session-keyed memory. Three registered buffers: buffer (256×384 ring of mean-pooled latents), buf_session (which session each slot came from), and write_ptr (ring position). These are state, not parameters.
  • Confidence-gated ring buffer. EpisodicWritePolicy.write stores a latent only when confidence ≥ confidence_threshold (default 0.5); the pointer advances modulo buffer_size (a true ring / FIFO over slots).
  • Cross-attention retrieval. forward() reads with read_head = MultiheadAttention(384, 6) over the whole buffer as keys/values: attended, _ = read_head(x, kv, kv).
  • Learnable memory gate. Fusion is fused = x + sigmoid(self.gate) · attended, with gate a scalar nn.Parameter initialised near identity (gate_init=0.1). forward() exposes last_read = {memory_query: x, memory_retrieved: attended} for the anchor loss.
Subtlety worth stating precisely In this study’s TTA loop, the optimiser only steps patch-embed + read-in, so during sleep the memory’s read_head and gate are not trained — they provide a fixed retrieval target while the encoder’s input layer is regularised toward the recalled latent. (The end-to-end training of the read head lives in the separate H2 experiment in the parent repo, per RESEARCH_NOTES §7.)

core/lm_refine.py — the fix for the N>1 collapse

core/lm_refine.py
class PhonemeNGramLM:
    def __init__(self, order=3, k=0.1)                 # add-k smoothing
    def fit(self, sequences: list[list[int]])           # train from seq_class_ids
    def logprob(self, token, context) -> float          # stupid backoff over context
    def save(path) / @classmethod load(path)

def ctc_beam_search(log_probs, lm=None, beam_size=8, lm_weight=0.5,
                    blank=0, max_frames=200) -> list[int]
  • Phoneme n-gram refinement. PhonemeNGramLM is a pure-Python n-gram (add-k + stupid backoff) over phoneme-ID sequences, trained by a100/build_lm.py from the dataset’s seq_class_ids. No external deps (a KenLM .arpa is an optional drop-in).
  • CTC beam search. ctc_beam_search is a CTC prefix beam search with shallow LM fusion: at each frame it expands the top emission tokens, adds lm_weight · lm.logprob(tok, prefix) when extending a prefix, and prunes to beam_size. Returns a collapsed, blank-free phoneme-ID list.
  • Why it fixes the N>1 collapse. The module docstring states the failure directly: “raw greedy CTC decodes on drifted signals are noisy; using them as gradient targets makes each consolidation step follow a slightly wrong direction, and N steps compound the error.” Replacing the greedy self-label with an LM-denoised label (condition C2) removes the compounding term so deeper N can help. A unit test (test_ctc_beam_search_recovers_clean_sequence) pins the decoder’s correctness on a clean toy signal.

core/replay.py — ZenBrain Simulation-Selection

core/replay.py
@dataclass
class ReplayItem:  neural, latent, confidence, surprise, session="", ref=None

class ReplayStore:
    def __init__(self, capacity=512, w_surprise=1.0, w_conf=1.0, w_novelty=1.0)
    def add(self, item)                       # FIFO eviction at capacity
    def priority(self, item) -> float          # the selection score
    def sample(self, k) -> list[ReplayItem]   # top-k by priority

The Simulation-Selection priority is computed exactly as the README states:

priority = w_surprise·|surprise| + w_conf·(1 − confidence) + w_novelty·novelty

  surprise   = the trial's CTC loss when decoded   (high → informative about drift)
  confidence = mean per-frame max-softmax prob      (low → more to learn)
  novelty    = 1 − max cosine-sim of this latent to recently-replayed latents

sample(k) ranks the store by priority, returns the top-k, and records their latents in a bounded recent-window (last 32) so novelty measures distance from what was just replayed. A unit test (test_replay_priority_and_sample) asserts the high-surprise item wins.

Grounding note on the automated read-off The README phrases the Hmain gate as a cross-condition comparison (C2 N>1 vs C1 N=1). The automated check in collect_and_plot.py implements a slightly tighter within-condition form: it finds C2’s best-N and reports “supported” iff that best N is > 1 and beats C2’s own N=1. Both express the same intent — deeper consolidation must beat single-step — but a defense should state which comparison a given figure is using.

6.  Findings Already Established (from RESEARCH_NOTES.md)

The design is not speculative — it is the response to a concrete, observed failure on toy data. These are the lessons that motivated lm_refine.py and the episodic anchor.

The observed failure: N>1 self-label collapse on toy data

Self-labeled TTA on a randomly-initialised encoder did not just fail to help — it made things worse, and worse with more steps. The parent notes record both the single-step regression and the runaway:

# RESEARCH_NOTES §8 — G2 run, random encoder, synthetic drift
   N   PER@day0   PER@last
   0    0.0000    0.2732     # drift instrument works: error grows with no adaptation
   1    0.0000    0.6388     # N=1 made it WORSE — confidence shot 0.07 → 0.97 (confident & wrong)

# Notes.md — the runaway with depth
   self-labeled TTA collapses: PER 0.64 → 4.2 for N = 1 → 8

Root causes (and why each caused the collapse)

#Root causeWhy it causes collapseWhere it is fixed
1The CTC head (and encoder) must be restored from the checkpoint. A randomly-initialised head produces garbage self-labels; one step of “update toward garbage” confirmation-biases the model into a confident-but-wrong attractor — and each extra step deepens it. model.build_ctc_model loads best_model_per.pth (encoder.* + head.*); the study runs on the trained head, not random init.
2Real neural data is required (random inputs fail). Random/synthetic inputs give the decoder no real structure to recover, so pseudo-labels are unreliable and N-step adaptation reinforces noise. drift_eval.load_real_sessions loads the real dated sessions with training-matched preprocessing; the headline grid runs on real chronological drift.
3A stable, gentle learning rate (1e-5). A large LR (the parent repo’s old 1e-3) overshoots per trial, amplifying the move toward the wrong attractor. configs/study.yaml and TTAConfig default both set lr=1e-5 — “gentle per-trial recalibration (avoids overshoot).”

How the failure motivated the two additions

→ LM-refined labels (C2) Collapse is a pseudo-label-quality problem: noisy greedy labels make each step follow a slightly wrong direction and N compounds it. The phoneme n-gram + CTC beam search (lm_refine.py) denoises the target so deeper N can move along the right direction — directly addressing the “bottleneck is label quality, not depth” branch of the decision gate.
→ Episodic-memory anchoring (C3) Even with better labels, repeated self-adaptation can drift the latent away from prior, stable representations. The episodic anchor adds MSE(current_latent, recalled_latent.detach()) to the loss, pulling the latent back toward what the model produced for similar past trials — a regulariser against the confident-but-wrong attractor, sourced from ZenBrain.
The mechanism does work in the right regime On a competent synthetic decoder (RESEARCH_NOTES §8 “mechanism demo”), deeper consolidation monotonically helped from N=1→4 (PER@last 0.955 → 0.765) before destabilising at N=8 — with wake latency flat (0.05–0.16 ms) and consolidate cost linear (3 → 4 → 24 → 101 ms). The conclusion the notes draw is that self-labeled TTA is bistable: it corrects drift only when label quality is sufficient — which is exactly what C2/C3/C4 are built to supply.

7.  Limitations and Open Questions

An honest accounting of what the current repository can and cannot claim.

Data realism — synthetic vs real drift

The only quantitative results presently in the repository come from synthetic drift on toy / randomly-initialised models (RESEARCH_NOTES §8: synthesize_drift applies progressive per-channel affine + noise). The standalone study adds the real chronological loader (load_real_sessions) and is wired to run on the real dated sessions, but the headline real-drift grid is an A100 job that is set up, not yet reported here — there is no results/study_results.json committed. Synthetic drift mimics the physical mechanism (impedance scale/shift + thermal noise) but is not a substitute for the real day-to-day distribution.

Oracle quality — the g2p oracle is approximate

The C4 “oracle” is only as good as its phoneme labels. DATA.md is explicit: the local preprocessed_data.h5 has no seq_class_ids, so Option A generates them with g2p_en(transcription) (a100/make_seq_class_ids.py). But the trained head was fit on the authors’ phonemization, so g2p is an approximate oracle — “good enough to test the mechanism; not the canonical number.” It must pass the --validate_with_model PER check; if that PER is high the inventory/ordering is wrong and Option B (re-obtaining the authors’ formatted data, Dryad doi:10.5061/dryad.dncjsxm85 — the T15 set, Card et al. NEJM 2024) is required for a faithful result.

Evaluation — PER vs canonical WER

Every cell always reports PER (the cheap, label-free-ish phoneme proxy); WER is computed only when a lexicon is supplied, and via a noisy-channel lexicon DP decoder (wer_decode.decode_words), not the canonical word-LM pipeline. The module docstring says so: this reproduces the transcription on clean labels (the self-check) but “for a fully faithful word LM you can instead use DietCorp’s own n-gram decoder.” So the WER numbers here are mechanism-level, not directly comparable to DietCorp’s published 12.17% without swapping in the canonical decoder. (When C2/C3 are requested but no LM is loaded, the driver explicitly warns and falls back to self-labels.)

Stability — instability at large N and a consolidation-depth ceiling

The sleep paper itself cautions that deeper recurrence “can make training slow and unstable,” and the repository’s own mechanism demo reproduces this: N=8 destabilised after N=4 was best. Gradient clipping (grad_clip=1.0) and the gentle lr=1e-5 mitigate but do not remove this. The practical expectation is therefore not “monotone forever” but an optimum at some N_opt (≈4–8) with a ceiling beyond it — and the design explicitly anticipates reporting that ceiling rather than assuming it away.

Net statement for a committee The repository delivers a complete, tested apparatus (10 CPU unit tests; standalone, dependency-free core) and a clear falsification protocol, but the real-data headline result is not yet in the repo. The strongest current evidence is mechanism-level (synthetic/toy): N-scaling helps in the good regime, collapses in the bad regime, and label quality is the pivot — which is precisely why C2 (LM), C3 (memory), and C4 (oracle ceiling) exist.
